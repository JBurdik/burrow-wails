Burrow — Changelog

Historie verzí v češtině. Co se změnilo a proč.
v2.24.3 nejnovější srpen 2026
Skutečné rozdělení karet
  • Aktivní kartu lze rozdělit doprava nebo dolů jako chat či terminál — fungují tak kombinace chat + chat, terminál + terminál i chat + terminál.
  • Každá plocha zůstává živá — vlastní konverzace a běžící PTY se při rozdělení nezahazují.
Přehled a řízení agentů
  • Agent Inspector ukazuje stav, pracovní adresář, terminál a poslední aktivitu; z něj lze terminál otevřít, poslat follow-up nebo agenta bezpečně zastavit.
  • Sidebar zvýrazňuje agenty vyžadující pozornost, dokončené nepřečtené úlohy i právě pracující agenty.
Burrow MCP pro práci s panely
  • read_pane přečte poslední scrollback PTY bez změny fokusu.
  • wait_pane čeká na výstup odpovídající textu nebo do timeoutu; používá stejný daemon socket jako terminály.
v2.24.2 červenec 2026
Live status u board tasků a kanban tabů
  • Board úkoly se spawnují jako reálné PTY taby — kanban úkoly teď dostanou skutečný terminal tab místo separátní cesty, takže mají stejný status dot a live embed jako ručně spawnutý agent.
  • Titlebar overlap a leak chat statusu opraveny — drobné UI chyby okolo titulkového pruhu a stavu chatu, které vypluly z předchozího refaktoru status stroje.
list_tabs/list-tabs teď hlásí live status
  • Root cause: status žil jen v paměti frontendu — leaf.status nastavuje agentStatusMachine ve Terminal.vue, ale nikdy se nepersistoval. burrow list-tabs i MCP list_tabs jsou čistě Rust/DB reads (bez round-tripu na frontend), takže vracely jen {ptyId,title} — status v tom payloadu strukturálně chyběl. Proto si Manager i jiní agenti kontrolující tab přes MCP/CLI často mysleli, že agent ještě neskončil.
  • Fix: status se zrcadlí na disk — při každém přechodu agentStatusMachine se zavolá nový příkaz set_tab_live_status, který zapíše status do <session>/tab_status/<ptyId>. query_tabs_tsv ho čte a přidává jako třetí sloupec; list_tabs teď vrací {ptyId,title,status} a burrow list-tabs tiskne <pty-id>\t<title>\t<status> (running/waiting/permission/done/review/error/idle).
Zvětšený task detail panel
  • TaskDetail.vue panel rozšířen (560px → 720px) a embed live chatu zvýšen (360px → 440px) — víc místa pro live terminál v detailu úkolu.
  • TaskLiveTerm.vue teď kopíruje přesnou mřížku zdrojového PTY místo dopočítávané velikosti fontu — Claude Code interaktivní UI (stavový řádek, rámečky) používá absolutní pozicování kurzoru vůči reálnému terminálu, takže neshodná mřížka renderovala rozmazaně/maličko. Panel teď škáluje přes CSS scroll (.tlt-viewport) místo interního scrollbacku xtermu; wheel eventy se zachytávají v capture fázi, protože xterm.js interní .xterm-viewport na ně volá preventDefault() a blokuje nativní scroll.
v2.24.1 červenec 2026
Status dotu má jednoho vlastníka
  • agentStatusMachine teď arbitruje všechny tři kanály — agent hooky, foreground poll i interrupt/watchdog šly dřív přes duplicitní logiku (terminalStatus.ts reducer + samostatný XState stroj). Sloučeno do jednoho stroje se třemi vstupními kanály; terminalStatus.ts teď drží jen čisté helpery (typy, priorita, agregace, název tabu).
  • FloatBubble.vue plovoucí terminál používá stejný stroj jako hlavní okno — místo ručně psaného reduceru teď běží vlastní agentStatusMachine instance nakrmená stejným pty-hook-{id} eventem, takže se chování status dotu neliší.
  • Vitest přišpendlen na v2 — v3+ vyžaduje vite ≥6, a vite zůstává na 5 kvůli Tauri. Přidán pnpm test skript.
v2.24.0 červenec 2026
Kanban board: MCP nástroje a ACP-only agenti
  • Typované MCP nástroje pro board — board_list/board_create/board_move vedle stávajícího burrow CLI. board_list/board_create odpovídají přímo z DB, board_move routuje přesun do „todo" přes stejný request-dir transport jako spawn/create_worktree (worktree + spawn agenta existuje jen na klientu); přesun do „done" je zamítnutý stejně jako u CLI. Kanban skill teď učí MCP nástroje jako první volbu, CLI jako fallback — a instaluje se globálně pro každého agenta, ne jen pro tenhle repo.
  • Board úkoly jen přes ACP — zrušena pty/terminal-tab cesta pro kanban úkoly; každý agent (Claude, Codex, Gemini, opencode…) teď běží jako embedded ACP chat session, takže výběr agenta není natvrdo na Claude CLI a board nepotřebuje live terminal embed ani follow-up-to-pty plumbing.
Konfigurace mimo localStorage
  • Root cause: localStorage sdílí adresář s WebView cache — na macOS žije Tauri WKWebView localStorage v ~/Library/WebKit/<bundle-id>, stejném adresáři jako vymazatelná HTTP/JS cache. Vyčištění „cache" kvůli zaseknutému buildu smazalo i ikony projektů, pořadí záložek a další nastavení uživatele.
  • Ikony a pořadí workspace tabů → SQLite — workspaces tabulka má nové sloupce icon/sort_order, nové Tauri příkazy set_workspace_icon/set_workspace_order. FloatBubble.vue opravena, aby ikonu četla ze store místo mrtvého localStorage klíče.
  • Zbytek konfigurace → config.json — nové Tauri příkazy read_config/write_config a frontendový helper src/lib/config.ts (getConfig/setConfig/migrateFromLocalStorage) přesouvají Claude profily, agent presety, UI preference, mobile pairing, historii chatů (zprávy, ACP nastavení, permission mode), Manager panel nastavení, titlebar preference a collapse stav Sidebaru — s jednorázovou automatickou migrací starých localStorage dat při prvním spuštění.
Burrow MCP token po restartu appky
  • Token se generoval při každém startu appky — burrow_mcp_socket.rs přepisoval burrow-mcp.token na každém spuštění, takže už připojená Claude Code session s cachovaným starým tokenem dostávala „unauthorized" po restartu Burrow appky. Token se teď generuje jen jednou a napříč restarty appky zůstává stejný.
v2.23.0 červenec 2026
Task karty: živý terminál a follow-up přímo v Kanban panelu
  • Vestavěný terminál v detailu úkolu — TaskDetail.vue teď embeduje živý XTerm přímo v kartě úkolu místo pouhého odkazu na záložku v hlavním okně. Tlačítko „Open tab" zůstává jako záložní cesta, když chceš úkol otevřít na celou obrazovku.

ACP zůstává dostupné pro běžné chatovací záložky mimo board.
Zastaralé názvy modelů

Kanban board pro orchestraci úkolů (Mission Control)

Přepínač je neaktivní, dokud neběží HTTP server a Tailscale není nainstalovaný a přihlášený; po zapnutí ukáže výslednou https://<dns-name>/ URL s vlastním tlačítkem na zkopírování.
v2.20.0 červenec 2026
MCP server pro sub-agenty
  • Burrow teď má vlastní MCP server — agenti dostávají nástroje spawn, create_worktree, list_workspaces, list_tabs, send_to_tab, focus_tab/focus_workspace, collect_results/wait_result a pr_create/pr_list/pr_view/pr_merge místo (nebo vedle) ručního volání CLI burrow. Přenos jde přes lokální Unix socket (chmod 0600 + bearer token), --burrow-mcp-stdio proxy je přímo aplikace samotná — žádný nový binární soubor.
  • Rekurzní hloubka je omezená — nastavitelný strop (Nastavení → Sub-agent delegation → MCP recursion depth, výchozí 3) brání sub-agentovi spustit sub-agenta do nekonečna. Nástroje pro spawnování to kontrolují, čtecí nástroje ne.
  • Dostupné odevšad — terminálová záložka spuštěná tlačítkem, Manager (plovoucí chat), nativní chat i ACP agenti (Codex, Gemini…) dostávají stejné MCP nástroje, každý svým vlastním mechanismem vstřikování configu. Ručně napsaný claude v shellu zatím pokrytý není.
  • Globální skill dokument teď učí agenty použít MCP nástroje jako první volbu, CLI burrow zůstává jako záloha pro shelly bez MCP.
Vzdálený přístup přes web/mobil (Tailscale)
  • HTTP/WebSocket server (vypnutý ve výchozím stavu, zapíná se v Nastavení → Remote access) zpřístupňuje celý backend přes jediný /ws endpoint — JSON-RPC dotaz {command, args} se vyřídí přes stejný dispatch_command router jako desktopová appka. Poslouchá výhradně na 127.0.0.1, nikdy na 0.0.0.0; vzdálený přístup se řeší přes tailscale serve, ne otevřením portu. Autorizace bearer tokenem (soubor chmod 0600), jen /healthz je bez ověření.
  • Mobilní webové rozhraní — nová stránka (/ na HTTP serveru) s obrazovkami Connect → Sessions → Terminal: připojení podle hostitele+tokenu, přehled workspaců/záložek se stejnými stavovými tečkami jako desktop, a živý terminál (přes xterm.js) s lištou pro Ctrl+C/Esc/Tab/šipky, protože mobilní klávesnice tyhle klávesy nemá. Ověřeno funkční z reálného telefonu přes Tailscale.
  • Centrální dispatch router (dispatch_command) sjednocuje 72 backendových příkazů za jedno rozhraní — díky tomu je stejná logika dosažitelná z Tauri IPC, MCP i HTTP/WS bez duplikace kódu.

Opravy

v2.18.5 červen 2026
Oprava — pád aplikace (SIGSEGV) při blokování spánku
  • Špatný typ argumentu ve volání IOKit — IOPMAssertionCreateWithName očekává CFStringRef, ale předávaly se mu syrové C-stringy (const char *). IOKit pak provedl CFRetain nad bajty řetězce, jako by šlo o objekt, a vložil je do své interní NSMutableDictionary → objc_retain nad neplatným ukazatelem → EXC_BAD_ACCESS. Adresa pádu 0x6e6576657270 odpovídala bajtům "preven" z řetězce "PreventUserIdleSystemSleep" čteným jako ukazatel.
  • Oprava — vytvoří se skutečné CFString objekty přes CFStringCreateWithCString, předají se do IOKitu a po volání se uvolní (CFRelease). Pád při dlouhoběžící agentní úloze (která drží assertion proti uspání) je tím odstraněn.
Diagramy pro agenty
  • Mermaid diagramy přes burrow diagram — agent může vizualizovat architekturu, toky nebo datové modely; Burrow vykreslí interaktivní SVG. Podporuje libovolný Mermaid typ (flowchart, sequenceDiagram, classDiagram, erDiagram, gantt…). Zdokumentováno ve skillu.
v2.18.4 červen 2026
Oprava — ACP „closed during handshake" při prvním spuštění
  • Claude (ACP) se nepřipojil — „adapter closed during handshake" — adaptér se spouští přes npx -y, který ho při prvním použití musí stáhnout. Velký balík @agentclientprotocol/claude-agent-acp (táhne s sebou celý claude-code) se nestihl stáhnout do 30s a watchdog ho zabil uprostřed stahování → „closed during handshake". Codex fungoval, protože jeho balík už byl v cache.
  • Předehřátí cache na startu — prewarm_acp_adapters() na pozadí při startu stáhne oba npx adaptéry do cache, takže skutečný handshake je už vždy rychlý. Best-effort, tichá chyba.
  • Watchdog 30s → 120s — tolerantnější k pomalému prvnímu stažení i na pomalejších strojích.
v2.18.3 červen 2026
Oprava — ACP po přepnutí agenta za běhu
  • ACP agent se zasekl v „thinking" bez modelu — listenery acp-data/acp-req se připojovaly jen když chat startoval jako ACP. Když chat naběhl jako Claude (výchozí) a uživatel přepnul na codex/gemini za běhu, listenery se nepřipojily a všechen výstup adaptéru (model, config i celý turn) padal do prázdna — backend přitom běžel správně. Připojení listenerů vytaženo do ensureAcpListeners() a volá se i při přepnutí agenta. Symetricky opraven i návrat na stream-json Claude.
  • Proč to v dev fungovalo a v buildu ne — localStorage je oddělený mezi tauri:dev (localhost) a zabaleným buildem (tauri://). V dev byl výchozí agent uložený jako ACP (chat startoval rovnou jako ACP, listenery OK), v buildu padl na Claude a přepínalo se ručně → bug.

v2.18.1 červen 2026
Opravy — ACP v produkčním buildu

v2.18.0 červen 2026
ACP — nativní podpora víc agentů v chatu
  • ACP transport (Agent Client Protocol) — Claude chat umí mluvit nejen přes stream-json, ale i přes ACP. Nová vrstva AgentTransport + parser ACP session/update zpráv (acpParser.ts) překládá ACP události na stejný model bublin a stavů, jaký už chat používá.

  • Effort dropdown — u ACP agentů, které to podporují, lze v hlavičce vybrat úroveň reasoning effortu (vedle výběru modelu a permission módu).
Backend — řízení ACP procesů
  • Rust ACP lifecycle — nové Tauri příkazy acp_start / acp_send / acp_stop / acp_respond_permission spravují ACP agentní proces stejným modelem jako existující Claude proc. Restart (přepnutí agenta/módu, abort) prochází sjednoceným restartClaude(), který pro ACP korektně zastaví a znovu nastartuje adaptér a vyšle INTERRUPT, takže status tečka nezůstane viset.
  • ACP v burrow CLI — burrow zná ACP schopnosti agentů, takže delegace a status fungují i pro ACP sezení.

  • Agent si umí sám ovládat aplikaci — burrow CLI má nově příkazy, kterými agent z terminálu řídí celé Burrow: burrow list-workspaces / list-tabs (vypíše projekty a taby), focus-workspace ID / focus-tab ID (přepne se), new-tab [--ws ID] [--cmd CMD] (otevře nový tab, klidně s příkazem). Čtecí příkazy odpovídá rovnou Rust (SQLite → výsledkový soubor), akce se posílají do UI — vše přes stávající file-based transport, žádné claude -p. Agent tak může proklikávat appku jako uživatel.
  • Lišta „Needs Attention" — nahoře v postranním panelu se sama objeví sekce se VŠEMI taby napříč projekty, které potřebují tvou pozornost: chyba, čeká na povolení, čeká na vstup nebo review (dokončeno, zatímco jsi byl pryč). Seřazené od nejnaléhavějšího (STATUS_PRIORITY), každý řádek „projekt · tab", klik skočí rovnou tam. Když není co řešit, lišta zmizí.
  • PR stav v postranním panelu — u každého worktree/projektu s otevřeným pull requestem se ukáže odznáček: číslo PR + barevný bod — zelená otevřený, šedá draft, fialová zmergovaný, červená padají CI checky, jantarová CI běží. Data přes gh pr view --json, cache, refresh á 60 s + na změnu větve. Degraduje elegantně bez gh (nic neukáže, nikdy nespadne, neblokuje UI).
  • Obyčejná složka jako workspace — do Burrow nově přidáš jakýkoli adresář, nejen git repo. Nový sloupec is_git (zpětně kompatibilní migrace) řídí, že se pro ne-git složku schovají git věci (větev v titulku, New Worktree, diff panel); terminály fungují normálně.
Opravy
  • Konec zaseklých status bodů — když agent spadne nebo ho zabiješ bez Stop hooku, jeho status hook teď nese PID procesu a Burrow ho periodicky ověří přes kill(pid,0); jakmile proces zmizí, bod se uklidí okamžitě místo čekání na pomalý dead-PTY watchdog (3 prázdné polly). PID se posílá jen pro lokální session (kontrola hostname), takže přes SSH nedojde k falešnému úklidu. Watchdog zůstává jako záloha.
v2.7.0 červen 2026
Claude UI — interaktivní řízení jako VS Code rozšíření
  • Povolování, dotazy i plány přímo v UI — vestavěný chat s Claudem (stream-json, na předplatném — žádné claude -p ani Agent SDK) teď zpracovává celý řídicí protokol přes skrytý přepínač --permission-prompt-tool stdio. Každé blokující rozhodnutí přijde do aplikace jako can_use_tool a vyřeší se v UI místo v terminálu — stejně jako to dělá oficiální VS Code rozšíření.
  • Bohatší povolení — místo prostého Ano/Ne nově Allow once / Allow always (zapamatuje si pravidlo, příště povolí samo) / Deny. Pro Bash se pravidlo váže na konkrétní příkaz, ne na celý nástroj.
  • Schvalování plánu (ExitPlanMode) — když Claude vyjde z plan mode, zobrazí se vykreslený plán + Approve / Keep planning (s možností napsat zpětnou vazbu, podle které Claude plán přepracuje).
  • Otázky s výběrem (AskUserQuestion) — Claude se může zeptat a vy odpovíte klikem na možnosti přímo v chatu (single i multi-select), místo psaní do terminálu.
  • Diff Accept / Reject u úprav souborů — Edit/Write/MultiEdit ukáže náhled navržené změny s tlačítky Accept / Reject (VS Code „review changes"). Reject s důvodem pošle Claudovi zpětnou vazbu.
  • Přepínač režimu oprávnění — v záhlaví chatu tlačítko cyklující Ask (ptá se) → Auto-edit (auto-přijme úpravy) → Bypass (přeskočí vše). Per-chat, pamatuje se. Nahrazuje binární „dangerous mode".
  • Editor kontext — @-mention & sdílení výběru — v chatu napíšete @ a doplníte cestu k souboru (z git ls-files). Tlačítko sdílení výběru vloží označený kód z editoru jako @soubor#Lx-Ly + blok kódu.
Další nové funkce
  • Terminal pets — volně pobíhající pixelová zvířátka v overlay nad agentskými taby. Vizuální cukrkandl per agent.
  • Přepínač workspace v Mission Control — záhlaví MC je nově rozbalovací výběr aktivního workspace (zrcadlí postranní panel). Nové úkoly cílí na vybraný.
  • Integrace v Nastavení + ntfy.sh — nová sekce Nastavení → Integrace pro napojení na externí služby. První integrace: push notifikace přes ntfy.sh. Burrow pošle upozornění na telefon/desktop, když agent dokončí tah nebo potřebuje pozornost.
  • Volitelné spouštěče pushů — vyberete, které přechody pushnou: hotovo, čeká na vstup, potřebuje povolení, chyba tahu. Volba „jen když nejsem u okna" potlačí pushe, dokud je okno Burrow v popředí. Nastavitelná URL serveru, téma a token; tlačítko „Send test".
Opravy
  • Debounce stavu „done" v Mission Control — backgroundovaný sub-agent nutí hlavní session parkovat a auto-resumovat, což střílelo průběžné Stop hooky a krátce nastavovalo done, hned přebité running. Nově se každé done krátce podrží; živý stav v okně ho zruší. Jen přeživší done je reálný konec tahu.
v2.6.0 červen 2026
Nové funkce
  • Živý feed zpráv v Mission Control — detail úkolu se dřív naplnil až po dokončení tahu (přes captureResult — jen poslední zpráva agenta). v2.5.0 červen 2026
Nové funkce
  • Stav „error" — selhání tahu je vidět — Claude Code posílá hook StopFailure, když tah skončí chybou API (rate limit, přetížení, selhání ověření, billing_error, chyba serveru…). Nově se tab/úkol obarví červeným pulzujícím bodem + ukáže proč (např. error: billing_error). Je to nejurgentnější stav — přebíjí i permission a drží, dokud ho neuvidíš. Dřív agent po pádu zůstal viset na zaseklém bodu bez vysvětlení; teď okamžitě víte, že došlo třeba na limit předplatného.
  • SessionStart — model a titulek bez hádání — hook SessionStart nese model, session_title a source (startup/resume). Tab i úkol v Mission Control se popíšou správně a ukážou běžící model, místo aby se odhadoval z výstupu PTY. Reattach po restartu se rozpozná přes source:"resume".
  • Mission Control se chová jako klasický terminál — MC dřív mělo vlastní zjednodušený model stavů (permission splynulo s waiting, žádné review). Nově zrcadlí kanonickou sadu stavů terminálových tabů: permission (jantarový bod — agent čeká na souhlas) je odlišený od waiting (modrá), a přibyl review (zelený puls — úkol dokončil, zatímco jste byli pryč; drží, dokud ho neotevřete). Jediný záměrný rozdíl od terminálu: dokončený úkol navíc zachytí transcript výsledku.
  • Mapování Notification — hook Notification nově rozlišuje typ: permission_prompt → permission, idle_prompt → waiting; ostatní typy zůstávají bez efektu (telemetrie).
Opravy
  • Permission stav správně zapojen + self-healing statusu — dropnutý statusový POST během ~3s okna přeobsazení portu se teď sám zhojí: sticky stavy (waiting/permission/done/error) zkoušejí až 3× s re-readem hook.port mezi pokusy. Opraven i zaseklý „waiting" v Mission Control.

v2.3.2 červen 2026
Nové funkce
  • Stav „permission" + zvonkový ikonka — Claude Code posílá hook PermissionRequest vždy, když potřebuje souhlas uživatele (spustit příkaz, smazat soubor…). Nově se zobrazuje jako jantarový pulzující bod + ikona zvonku v postranním panelu — vizuálně odlišný od modrého bodu „čeká na další zprávu". Dřív se obojí promíchalo dohromady a nešlo poznat, co agent potřebuje.
  • Čítač zpráv ↺N — každé odeslání zprávy agentovi navýší čítač. V postranním panelu se u tabu zobrazí ↺2, ↺3… pokud jste poslali víc než jednu zprávu a tab je aktivní. Tooltip ukazuje „N messages sent to agent this session". Na první pohled vidíte, kolikátá konverzační výměna právě probíhá.
  • OSC 133 — okamžité detekování příkazů v shellu — shell (zsh, bash, fish, iTerm2) posílá markery C (příkaz začal) a D (příkaz skončil) přes OSC 133. Burrow je teď čte a okamžitě přepíná stav tabu na „busy/idle" — bez čekání na 2s polling. Funguje jen pro terminálové taby bez agenta; agentské taby řídí stav přes hooky.
  • Inline přejmenování tabu v postranním panelu — dvojklik na název tabu ho otevře jako editovatelné pole přímo na místě. Enter nebo blur potvrdí, Esc zruší.
  • Titulek okna OS = aktivní tab — záhlaví macOS okna teď zobrazuje „popis úkolu — workspace", takže je vidět co agent dělá bez přepnutí do Burrow.
  • OSC 7 — živé sledování adresáře (CWD) — shell emituje OSC 7 po každém cd. Burrow ho čte a aktualizuje leaf.cwd ihned, bez pollingu. burrow spawn --cwd tak vždy dostane správnou cestu i když agent přejde do podadresáře.
Opravy
  • SessionStart nespouští stav „running" — Claude Code posílá hook SessionStart při každém spuštění. Ten se dřív mapoval na running, takže každý nový tab okamžitě dostal oranžový puntík ještě před tím, než uživatel cokoliv napsal. Teď se SessionStart ignoruje.
  • Titulek tabu se po dokončení nezamění na „Claude Code" — Claude Code po skončení úkolu resetuje OSC titulek na ✳ Claude Code (idle stav). To přepisovalo smysluplný popis úkolu. Nově se blokuje pouze tento konkrétní idle titulek — ostatní OSC titulky (např. z /rename příkazu) projdou. Ověřeno přímým zachycením PTY výstupu: Claude Code emituje automaticky jen OSC 0;✳ Claude Code při startu a nic jiného.
  • Funguje /rename příkaz Claude Code — pokud v Claude Code napíšeš /rename "Můj úkol", titulek tabu se v Burrow aktualizuje. Předchozí příliš agresivní freeze blokoval i manuální přejmenování. Tip: /color pro změnu barvy.
  • Titulek tabu neukazuje název adresáře místo popisu úkolu — oprava v2 — předchozí oprava (pendingOscTitle jen při isAgentSession=true) zahazovala i startup OSC titulek Claude Code (✳ Claude Code), protože ten přichází PŘED prvním pollem (2 s). Nová logika: vždy bufferovat, ale smysluplný titulek (má mezeru nebo Unicode) nesmí být přepsán shell cwd šumem (krátké slovo bez mezer). Shell async precmd emituje OSC 2;work po trySend — to teď prohraje s ✳ Claude Code.
  • Přejmenování tabu (dvojklik) nefungovalo — input se zobrazil, ale nefocusoval — Tauri webview vyžaduje explicitní focus() před select(). Opraveno.
