agentic-ide

Desktop IDE shell for running AI coding agents — Tauri + Vue 3 + Rust PTY

What it is

A native macOS desktop app (built with Tauri 2) designed as a minimal workspace shell around AI coding agents. It is not a code editor — it has no text editor pane. Instead it provides: a workspace picker, a real multi-tab split-pane terminal (PTY via Rust), a file explorer, a git panel, and a one-click agent launcher toolbar. The core idea: open a folder, click an agent button, agent runs in a terminal tab inside that workspace.

App control — one verb registry, three doors

  • Every app action an agent may take is a verb in src-wails/internal/control: delegation + supervision (spawn, agent_status, tab_output, send_to_tab, wait_result, collect_results), navigation, worktrees, git reads, PRs
  • Reachable as burrow <verb> [--arg v] (loopback HTTP + control.token), as MCP tools via burrow-mcp, and from the UI — one implementation, so they can't drift
  • spawn takes a task, not a command line; the frontend builds the command from Settings → Providers. Subscription-safe: interactive only, never claude -p
  • UI-only verbs emit control:action and block for the frontend's ack, so spawn returns the new tab's pty_id (this replaced the 1 Hz request-dir poll)
  • Verbs are local-only unless they opt into ScopeRemote — a phone can read and navigate, not spawn
  • Full reference →

Manager — per-repo orchestrator

  • ManagerPanel.vue in the right panel: a persistent chat that orchestrates and never implements. Message stream, composer, permission gates and model picker come from AgentChat; the panel owns only the thread and the primer
  • Keyed by the root repo id (climbs parent_id), so one Manager survives hopping between a repo and its worktrees. Threads stay mounted per engaged repo and toggle with v-show, so a busy Manager keeps streaming while you look elsewhere. Its session is flagged control:true and excluded from the Sidebar chat list
  • Its primer is generated from the verb registry (control_verbs) plus the worktree-isolation toggle and the project's .burrow/manager.md — it can't advertise a tool that doesn't exist. Any configured agent can be the Manager: MCP tools when it has them, burrow <verb> otherwise
  • Destructive verbs (worktree_remove, pr_merge, tab_close) require user confirmation first

Claude chat — unified Sidebar list & permission alerts

  • Chats and terminal tabs render as one Sidebar list distinguished only by icon (ClaudeIcon vs PhTerminal/PhRobot) — no separate "Chats" header; "New chat" sits on the workspace header row
  • A chat session carries the same status as terminal tabs (chatStatus() → permission+bell for tool/edit gates, waiting for question/plan, running mid-turn)
  • A permission request fires an in-app toast + (when unfocused) a native OS notification (notifyPermission()); switching permission mode no longer fires a spurious "finished" toast (the restart's teardown exit is squelched by suppressNextDone)

Agent status flows: globally-installed hooks → burrow hook → burrow status → HTTP server → pty-hook-{id} event → XTerm.vue. Installed on every launch by installStatusHooks (src-wails/statushooks.go) into ~/.claude/settings.json, ~/.codex/hooks.json, ~/.copilot/hooks/burrow.json, any CLAUDE_CONFIG_DIR/CODEX_HOME/COPILOT_HOME the app inherited, plus every per-instance config dir set in Settings → Providers. Merge is additive + marker-deduped, so other tools' hooks survive. The same pass installs the agent docs (src-wails/agentdocs.go): the /burrow skill wholesale into <dir>/skills/burrow/SKILL.md (Claude + Copilot, the latter also registered in skillDirectories), and a <!-- BURROW:BEGIN/END --> block in ~/.claude/CLAUDE.md / ~/.codex/AGENTS.md. Doc bodies are markdown files under src-wails/agentdocs/; .claude/skills/burrow in the repo is a symlink to the same source. See burrow.html for the full mechanism.

What's New — v2.3.x

Fix: SessionStart no longer triggers "running"

Claude Code fires a SessionStart hook on every launch. Previously burrow hook mapped this to running, so fresh tabs opened with an orange/working dot before any prompt was sent. Fix: SessionStart now exit 0s in the burrow script and is removed from the registered hook event arrays in lib.rs. The burrow script is re-written to disk on every PTY spawn, so existing installs get the fix automatically.

Fix: Agent tab title tracks task description dynamically

Claude Code emits OSC 0;✳ Claude Code at startup, then updates the tab title to the current task description as the session progresses. Two fixes were needed:

  1. Idle revert blocked: after Stop, Claude resets its title to ✳ Claude Code. hookState tracks when a turn is done; onTitleChange blocks only that specific idle reset — other OSC titles pass through.
  2. Startup title preserved: Claude's startup OSC 0 arrives before the first 2 s poll sets foreground. pendingOscTitle now always buffers it. Shell precmd/preexec cwd noise (bare words like work, agentic-ide) cannot overwrite a meaningful title (one with spaces/Unicode) — priority: non-cwd > cwd.

Feat: OSC 7 live CWD tracking

Shells (zsh, bash, fish) emit OSC 7;file://host/path on every directory change. XTerm.vue now parses this sequence and emits a cwd event; Terminal.vue updates leaf.cwd immediately — no polling required. This keeps spawn --cwd accurate when an agent cds into a sub-directory mid-session.

Feat: Double-click inline tab rename

Double-click any tab label in the Sidebar to rename it in-place. An inline <input> replaces the label (transparent background, accent-colored underline). Press Enter or blur to commit; Esc to cancel. Implemented via a store-based request (terminalTabs.rename(wsId, tabId, title)) — same pattern as activate/add/close. Terminal.vue watches the request and sets leaf.title on all leaves of the affected tab.

Feat: OSC 133 shell command boundary tracking

Shells (zsh, bash, fish, iTerm2-compatible) emit OSC 133;C on command-start and OSC 133;D on command-done. XTerm.vue now parses these markers and immediately emits busy(true/false) for non-agent sessions — no more waiting 2 s for the foreground poll to detect that npm install finished. No-op for agent tabs (hooks remain authoritative). Shell integration opt-in: users need the standard precmd/preexec hooks in their shell config (same hooks that power iTerm2/Warp shell integration).

Feat: Agent round counter

Each distinct "running" episode — i.e. each time the user sends a new prompt — increments a round counter on the leaf. The highest round across all leaves of a tab is published to the terminalTabs store and shown as a compact number (3) next to the status dot in the Sidebar, but only when > 1 and the tab is active. Lets you glance at the sidebar and know "this agent is on its third message exchange" without opening the terminal.

Feat: Permission request state + bell icon

Claude Code's PermissionRequest hook event now maps to a distinct "permission" agent state (previously collapsed into "waiting"). Surfaces as an amber pulsing dot (highest-priority status) + a bell icon in the Sidebar tab row — visually distinct from the blue "waiting for prompt" dot. The burrow script maps PermissionRequest → burrow status permission; terminalStatus.ts handles it like waiting (busy=true, plays waiting sound) but with its own TermStatus value so the UI can style it differently. Ctrl+C clears permission state (same as running/waiting).

Feat: Error state + session metadata

Two new signals ride the pty-hook-{id} channel (payload is now a bare state string for the legacy states, or an object {state, detail?|model?|source?|title?} for the two new ones).

error — Claude's StopFailure hook (turn ended on an API error: rate_limit, overloaded, authentication_failed, billing_error, server_error…). The error_type rides through as detail. Surfaces as a red pulsing dot and is the highest-priority status in STATUS_PRIORITY (error > permission > waiting > running > review > done > idle) — the user must see a failed turn first. Like review it persists until the tab is seen (markTabSeen); it never auto-clears, even while watching. The detail string shows as the dot's tooltip. A fresh running turn clears it.

session (SessionStart) — NOT a status: pure metadata (model/source/title). XTerm.vue forwards it via a separate agentMeta emit; Terminal.vue stashes leaf.model + leaf.sessionTitle, prefers the session title only over a generic "Terminal N" default (never clobbers an agent-set task title), and shows the model unobtrusively as the tab tooltip.

Fix: Status pipeline reliability

Hardened the hook→dot path against silent loss: (1) sticky states (waiting/permission/done) in burrow status retry up to 3× with a hook.port re-read, so a POST dropped during the ~3 s port-reclaim window self-heals (running stays a single fast attempt — it self-corrects on the next tool event). (2) Port resolution is now file-first everywhere (authoritative hook.port over the stale-after-restart env port). (3) The background_tasks "interim Stop" check is scoped to that JSON array slice, so an unrelated "status":"running" can't false-positive into a never-ending turn. (4) A dead-PTY watchdog in the 2 s poll settles a stuck in-flight dot when the foreground reads empty for ≥3 polls and list_pty_sessions confirms the PTY is dead — covers an agent killed/crashed with no Stop. See burrow.html.

Feat: OS window title syncs to active tab

The macOS window title bar now reflects the active tab: "task description — workspace name" when the tab has a distinct title, falling back to just the workspace name or "Burrow". Implemented as a watch in App.vue that calls getCurrentWindow().setTitle() via a lazy import() (so browser-only pnpm dev doesn't crash).

OSC Escape Sequences

SequenceDirectionMeaning
OSC 0 ; title BELPTY → appTab title + icon name (xterm). Claude emits this at startup (✳ Claude Code) and dynamically as the task description changes. Idle reset (✳ Claude Code) frozen after done; task titles pass through.
OSC 7 ; file://host/path BELPTY → appShell CWD hint — updates leaf.cwd live, no polling
OSC 133 ; C BELPTY → appShell: command started (non-agent tabs) → immediate busy=true, no poll wait
OSC 133 ; D BELPTY → appShell: command done → immediate busy=false
OSC 9998 ; running BELPTY → appAgent processing (UserPromptSubmit / PreToolUse / PostToolUse hook)
OSC 9998 ; waiting BELPTY → appAgent waiting for user input (Stop hook + idle Notification)
OSC 9998 ; permission BELPTY → appAgent needs permission decision (PermissionRequest hook) — amber bell
OSC 9998 ; done BELPTY → appAgent turn complete (Stop / SessionEnd hook)
OSC 9999 ; spawn ; … BELPTY → appLegacy direct-PTY spawn (latent parser — burrow CLI no longer emits this)

Note: OSC 9998 writes go via burrow hook → burrow status → HTTP server → pty-hook-{id} Tauri event → XTerm.vue. The OSC channel itself is only used internally by the old path; the HTTP path is primary.

PathPicker (in-app file/folder picker)

src/components/PathPicker.vue + src/lib/pickPath.ts replace every native NSOpenPanel call in the app. pickDir() browses folders (⌘↵ creates the typed one via the Go CreateDir binding); pickFile({extensions}) lists folders + matching files with a preview pane — image thumbnail, or a play button for audio (⌥↵ plays). Only the selected file is read off disk (read_file_base64 → data URL, so WKWebView gets an explicit MIME). Used by: add project (Spotlight/Sidebar/WorkspaceScreen/App), worktrees dir, Claude profile config dir, workspace icon, notification sounds, wallpaper. The @tauri-apps/plugin-dialog shim and src-wails/dialog.go stay in the tree unused, for a future multi-select need.

Everything except the ranges (⌘1–9, ⌃1–9, ⌘⇧1–5) is rebindable: the registry lives in src/lib/keymap.ts, user overrides in config.json under keybindings (hand-editable), edited in Settings → Keybindings. App.vue and Terminal.vue match keydowns through src/stores/keybindings.ts, so the palette, the ⌘/ cheatsheet and Settings all show what actually fires.
