The control API & the burrow CLI

One set of verbs for driving the running app — delegating to sub-agents, supervising them, managing worktrees and pull requests — reachable from a shell, from MCP, and from the UI itself.

The idea

Everything an agent may do to the app is a verb in one registry (src-wails/internal/control). The registry knows nothing about HTTP, MCP or Wails: it takes its capabilities as interfaces (database, git/gh/exec runners, PTY writer, worktrees, a UI bridge) and exposes Call(scope, name, params). Transports sit on top of it.

That is the whole point: one implementation, three doors. An MCP tool cannot behave differently from the same verb typed in a shell, and burrow help, the MCP tool schemas and the Manager's system prompt are all generated from the registry, so none of them can advertise something the app can't do.

Subscription-safe by design. Sub-agents are launched interactively — never claude -p / --print, never codex exec, never an Agent SDK. spawn takes a task and the frontend builds the command from the user's configured agents, so no caller can inject a non-interactive flag.

The loopback listener shares the hook server's ephemeral port, so an agent's shell needs exactly one port file ($BURROW_HOME_DIR/hook.port) and one token file (control.token, mode 0600). Loopback is reachable by every process on the machine and spawn starts programs, hence the token — and it fails closed if the token could not be persisted.

Scope is opt-in. A verb is local-only unless it declares ScopeRemote. A phone can list and focus things, read status and diffs; it cannot spawn, run, close tabs, remove worktrees or merge PRs. Adding a verb without thinking about the network leaves it off the network.

Using the CLI

burrow <verb> [POSITIONAL...] [--arg value] [--flag]
  • Verb and argument names may be written with dashes; the API speaks snake_case (worktree-remove → worktree_remove).
  • Positional arguments fill each verb's primary parameters in order (burrow send-to-tab 42 "hi"), everything else is --named.
  • A bare flag is true (--force, --squash, --stat).
  • cwd always rides along from $BURROW_CWD, so verbs resolve "this repo" without the agent knowing workspace ids.
  • Output is the verb's JSON result on stdout; errors go to stderr with a non-zero exit.
  • burrow help prints the live registry.

The script needs only curl and sed — no python3, no node, no controlling terminal — which is what lets it work from Claude's Bash tool and from hook subprocesses.

Verbs only the UI can perform

Opening a tab, focusing a workspace and reading a terminal's scrollback live in the frontend. Those verbs call UIBridge.Do, which emits a control:action event and blocks for the frontend's ack: 

burrow spawn "fix the cache bug"
  → POST /v1/spawn                      (CLI → app, token-authenticated)
  → verb allocates a result token
  → emit control:action {id, action:"spawn", args}
  → src/lib/controlBridge.ts performs it:
      resolve the agent + model → buildTerminalCommand()
      open the target workspace (the worktree, if cwd is one)
      tabsStore.add(ws, cmd, {cwd, resultToken, background})
      Terminal.vue creates the tab → fulfillAdd(nonce, ptyId)
  → invoke("ack_control_action", {id, resultJson})
  → verb returns {"pty_id":37,"token":"res1712…","target":"tab"}
  • One app-wide listener, not one per Terminal: actions are addressed by workspace/pty id, so "is that workspace mounted?" stops being the agent's problem.
  • Requests are keyed by id and tracked in a map, so a Manager spawning three agents at once gets three answers back — the Sidebar's single-slot request ref would have clobbered them.
  • A UI that never answers (window closed, JS exception) surfaces as an error after 15 s instead of hanging the agent.
This replaced a file-based transport: burrow spawn used to drop a request dir under $BURROW_SESSION_DIR/requests/ that every mounted Terminal.vue polled at 1 Hz, with DB-arbitrated rules deciding which one got to claim it. Gone with it: the 1 s latency, the claim race, the "target workspace must be mounted" caveat, and the split of one verb's logic across Go and Vue.

Result capture (still files)

A spawned agent's result does travel as files, because the writer is a hook in another process and the result must survive an app restart:

  • spawn allocates token and passes it to the new tab as Leaf.resultToken.
  • XTerm.vue injects a per-launch --settings whose Stop hook runs burrow capture <token>.
  • burrow capture reads the Stop-hook JSON on stdin, extracts the last assistant message from the transcript, writes <token>.result + .done, calls burrow status done (the per-launch hook takes precedence over the global one, so without this the dot would stick), then POSTs /agent-done so the app emits control:result.
  • wait_result polls for .done; collect_results drains every finished token. Both consume what they return, so a result is never reported twice.

Status plumbing (not verbs)

These keep their own bare-POST transport, because they have to work before the control API is up and are invoked by hooks rather than by an agent's reasoning:

SubcommandRole
burrow statusReport this tab's agent state to /hook: running, waiting, permission, done, error --detail, session --model/--source/--title, plus --pid for the liveness sweep. Port resolution is file-first (hook.port is rewritten every launch; the baked BURROW_HOOK_PORT goes stale after a restart). Sticky states retry 3×; running takes one fast attempt.
burrow hookInvoked by the globally-installed Claude/Codex hooks; maps hook_event_name → state with sed, no node/jq.
burrow notifyLegacy Codex notify-program path, kept as a fallback.
burrow captureResult capture, above.
Bug worth remembering: the CLI has always posted status to /hook, but the Go hook server only served /status. Because the CLI uses curl -sf and exits 0 on failure, every status dot silently depended on an endpoint that answered 404. Both paths are served now.

MCP server

burrow-mcp (src-wails/cmd/burrow-mcp, built and signed into the bundle) exposes the same verbs as MCP tools: tools/list is /v1/_verbs translated into JSON schemas (so a client sends 42, not "42", where a verb wants a number) and tools/call is one POST. It holds no database and no logic of its own.

It's injected into chat sessions automatically — Claude via --mcp-config, ACP agents via session/new — and skipped silently when the sidecar isn't next to the executable (a wails dev run), because the CLI on PATH is always there as the universal path. A failed tool call comes back as a result with isError and the verb's own message, so the model can adapt instead of seeing a broken transport.

How agents discover the CLI

installAgentDocs (src-wails/agentdocs.go, at startup) writes into every known config dir:

  • Claude — the burrow skill at <dir>/skills/burrow/SKILL.md, plus a short always-in-context rule in <dir>/CLAUDE.md inside a managed <!-- BURROW:BEGIN/END --> block, so Claude reaches for burrow spawn before its own in-process Agent tool.
  • Codex — the same content as a managed block in <dir>/AGENTS.md (no skill mechanism).
  • Copilot — the skill, plus its skills dir registered in settings.json's skillDirectories (Copilot has no implicit lookup).

Files & environment

NameMeaning
BURROW_HOME_DIRApp data dir; holds hook.port, control.token, bin/, sessions/.
BURROW_SESSION_DIRWhere result files live (<token>.result, .done).
BURROW_CWDThe workspace dir this shell belongs to — every verb's default cwd.
BURROW_PTY_IDThis tab's pty id. Set in PTYs only; its absence is what makes the global status hooks a no-op outside Burrow (and in chats, which are not tabs).
BURROW_HOOK_PORTPort baked in at PTY creation; the hook.port file wins when they disagree.

Chat sessions (Claude and ACP alike) get the burrow bin on PATH and the same BURROW_* values minus BURROW_PTY_ID — without that an ACP agent such as Codex or Gemini could not act as a Manager at all.

Examples

# Delegate three independent pieces, keep working, collect later
burrow spawn "Add tests for src/lib/cache.ts. Do not touch src/components." --model claude-sonnet-5
burrow spawn "Rename useFoo to useBar across src/. Mechanical only." --model claude-haiku-4-5-20251001
burrow spawn "Investigate the flaky terminal resize test. Report findings, change nothing." --agent codex
burrow collect-results

# Isolate parallel work in worktrees
path=$(burrow create-worktree feat/cache-fix | sed -n 's/.*"path":"\([^"]*\)".*/\1/p')
burrow spawn "Implement the cache fix." --cwd "$path"

# Supervise
burrow agent-status
burrow tab-output 37 --lines 120
burrow send-to-tab 37 "You also need to update the snapshot test."

# Ship
burrow git-diff --rev main..HEAD --stat
burrow pr-create --title "Fix cache invalidation" --body "Closes #42" --cwd "$path"
