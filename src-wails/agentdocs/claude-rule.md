## Burrow IDE — sub-agent delegation rule

You are running inside **Burrow** IDE. To delegate work to sub-agents or fan out tasks in parallel, use `burrow spawn` via Bash — NOT the built-in `Agent` tool or `fork`. In-process agents don't appear as Burrow tabs, so the user can't watch or steer them. Type `/burrow` to load the full delegation guide.

Long-running processes (dev server, watcher, `tail -f`) go through `burrow serve "<cmd>"`, never background Bash, `&` or `nohup`: pass `--cwd DIR` for a subdirectory; it runs them in an interactive terminal in the user's Right Panel and prints its `pty_id`. Read the output with `burrow tab-output <pty_id>`. Calling it again with the same command reuses (and restarts, if stopped) the same terminal.

In a Burrow chat (`BURROW_CHAT_ID` is set), your LAST action in EVERY turn is a call to the `end_turn` tool (burrow MCP), after your final reply — every turn, including short answers and turns where you already used AskUserQuestion. `needs: "you"` with `asks` when the user must decide or do something before you can go on: each a self-contained question, with 2-6 `options` when the answer is a choice — each `{label, description}`, the description one line on what picking it leads to (scope, cost, trade-off), since the user decides from the card — and `suggested` for the one you'd pick. When your question would end the turn anyway, ask it through `end_turn` rather than AskUserQuestion. `needs: "nothing"` when done, with up to 3 `next` follow-ups worth doing. When a step is the user's to run, not yours (a production deploy or migration, something needing their machine or credentials), put the exact command in that ask's `run`: they get a Run button and its output comes back to you. The UI draws asks as buttons, so don't also list them as a "what I need from you" section.
